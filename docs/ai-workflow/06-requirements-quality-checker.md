# requirements-quality-checker.md

> Pipeline Step 4
>
> Runs after normalizer.md.
>
> Evaluates the quality, completeness, clarity, and testability of normalized Intent Units before QA analysis begins.
>
> Purpose:
>
> Prevent poor requirements from flowing into risk analysis, traceability, and test generation.

---

# Responsibility

Assess requirement quality.

Do NOT:

* Generate test cases
* Generate automation
* Generate Playwright code
* Perform risk scoring
* Generate coverage analysis
* Modify Intent Units

This skill evaluates quality only.

---

# Input Contract

Consumes:

* Input Detection Report
* Approved Intent Preview
* Normalized Intent Units
* Original Artifact(s)

Generated by:

* input-detector.md
* intent-preview.md
* normalizer.md

This skill must not:

* Re-detect artifacts
* Recreate Intent Candidates
* Create new Intent Units

---

# Core Principle

A requirement may be traceable but still be poor quality.

Example:

"The system shall validate the account."

Traceable:
✓ Yes

Testable:
✗ No

Quality Checker exists to identify these issues before QA analysis.

---

# Evaluation Dimensions

Evaluate every Intent Unit against:

1. Clarity
2. Completeness
3. Testability
4. Ambiguity
5. Consistency
6. Traceability
7. Business Rule Definition

---

# Clarity Check

Question:

Can a reader understand the behavior without interpretation?

Flag:

⚠ UNCLEAR

Examples:

Bad:

"System validates account"

Good:

"System validates that the account status is Active before transfer submission"

---

# Completeness Check

Verify presence of:

* Actor
* Action
* Outcome
* Evidence
* Source
* Artifact ID

Missing fields:

⚠ INCOMPLETE

---

# Testability Check

Question:

Can QA verify the outcome objectively?

Pass Example:

Outcome:
Transfer is submitted successfully.

Fail Example:

Outcome:
Transfer is processed correctly.

Flag:

🚫 UNTESTABLE

Reason:
Observable result not defined.

---

# Ambiguity Check

Look for:

* appropriate
* proper
* valid
* correct
* successfully
* as needed
* if required
* supported
* optimized

Flag:

⚠ AMBIGUOUS

Example:

"The system validates proper account details."

---

# Missing Business Rule Check

Look for actions that require business rules but have none.

Examples:

* Validation without criteria
* Approval without conditions
* Eligibility without rules
* Calculation without formula

Flag:

⚠ MISSING BUSINESS RULE

Example:

Action:
Validate account

Missing:
Validation criteria

---

# Consistency Check

Detect contradictions between IUs.

Example:

IU-001
Transfer allowed EGP → USD

IU-014
Transfer not allowed EGP → USD

Flag:

❌ CONFLICT

---

# Traceability Check

Verify:

IU
↓
IC
↓
Artifact

exists for every requirement.

Missing links:

❌ TRACEABILITY GAP

---

# Requirement Quality Score

Calculate:

100

* Clarity deductions
* Completeness deductions
* Ambiguity deductions
* Testability deductions
* Consistency deductions

Output:

Quality Score : 87 / 100

Quality Grade : B

---

# Quality Grades

A = 90-100

Ready for QA Analysis

B = 80-89

Minor issues

C = 70-79

Moderate issues

D = 60-69

Major issues

F = Below 60

Requirements need correction
