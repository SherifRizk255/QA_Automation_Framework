# normalizer.md

> Step 2 of the pipeline.
> Runs only after input-detector.md completes and receives approval.
> Converts confirmed Intent Candidates into Intent Units (IUs).
> Produces a normalized, traceable, testable behavior model.

---

# ENTRY REQUIREMENT (MANDATORY)
# Approval Requirement

Normalizer may execute ONLY when:

- Intent Preview has been completed
AND
- User explicitly approved the intent map

Valid approvals:

APPROVE_INTENTS
NORMALIZE
RUN_NORMALIZER

If approval is absent:

STOP

Output:

Normalization blocked.
Intent Preview approval is required.

---
# Input Contract

Consumes:

- Approved Intent Preview
- Input Detection Report
- Original Artifact(s)
- Artifact Inventory

Generated by:

- input-detector.md
- intent-preview.md

This skill must not re-detect artifact type.

This skill must not regenerate Intent Candidates.

This skill must normalize approved Intent Candidates into Intent Units.

---


# Responsibility

Convert approved Intent Candidates into normalized Intent Units.

Do NOT:

- Generate test cases
- Perform risk scoring
- Produce coverage analysis
- Produce regression scope

Those belong to downstream skills.

---

# Core Principle

Intent Candidates (ICs) are approved behavior candidates.

Intent Units (IUs) are the canonical representation of those approved behaviors.

The purpose of this skill is:

IC → IU normalization

This skill does NOT discover new behaviors.

This skill does NOT create new requirements.

This skill does NOT expand requirements.

Every IU must originate from at least one approved IC.

---

# Intent Candidate Mapping Rule

Every Intent Unit must originate from one or more approved Intent Candidates.

Format:

IC-BRD-001
      ↓
IU-BRD-001

IC-BRD-002
      ↓
IU-BRD-002

No IU may exist without a parent IC.

Violation = Traceability Failure.

If a behavior exists in the source artifact but was not approved during Intent Preview:

Do not create an IU.

Place it under:

Rejected Candidate Behaviors.

---

# Intent Candidate Conversion Rules

An IC may become an IU only when:

1. User approved the IC list
OR
2. User explicitly instructed the pipeline to continue

Otherwise:

STOP.

Output:

Intent Candidates are pending confirmation.
No Intent Units generated.

---

# Testability Rule

Every IU must answer:

- Who performs the action?
- What action occurs?
- Under what condition?
- What observable outcome occurs?

If any answer is missing:

Mark:

⚠ INCOMPLETE IU

and report it.

---

# Normalization Rules by Mode

The parsing phase is complete.

The Normalizer must use:

- Approved Intent Candidates
- Original Artifact
- Detection Metadata

only to enrich traceability and completeness.

Mode affects metadata only.

The Normalizer must not create new behaviors.

Examples:

Story Mode:
IC → IU


BRD Mode:
IC → IU

CR Mode:
IC → IU

Feature Mode:
IC → IU

SDD Mode:
IC → IU

Visual Mode:
IC → IU

The transformation is normalization only.

# Rejected Candidate Behaviors

Behaviors that were:

- inferred
- not approved
- unsupported by evidence
- removed by user correction

must not become Intent Units.

Format:

RCB-001

Reason:
Not explicitly approved.

Evidence:
None.

Disposition:
Excluded from normalization.

# Quality Controls

## No Duplicate Behaviors

If two requirements describe the same behavior:

Merge them.

Keep all source references.

---

## No New Behavior Rule

Normalizer must never create new behaviors.

Allowed:

IC → IU

Not Allowed:

Requirement → New Behavior

Feature → New Behavior

Inference → New Behavior

If a behavior was not approved in Intent Preview:

It must not become an IU.

---

## Untestable Requirement Rule

If behavior cannot be verified:

Do not generate an IU.

Report:

🚫 UNTESTABLE

Include reason.

---

## Missing Information Rule

If critical information is missing:

Generate IU with:

status : Incomplete

and flag it.

---

## Traceability Preservation Rule

Never lose:

- Source section
- Source line
- Source artifact
- Original Intent Candidate

Every IU must be traceable back to its origin.
