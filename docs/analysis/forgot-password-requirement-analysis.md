# Forgot Password - Requirement Analysis

## Feature Overview
- **Module**: Internet Banking Retail Portal
- **Feature**: Forgot Password
- **Type**: Self-Service Account Recovery
- **Analysis Date**: 2026-06-12

---

## Feature Purpose
Allow registered Internet Banking users to reset their portal password via a multi-factor verification flow that includes username/National ID verification followed by an OTP sent to the user's registered mobile number and retrieved from the CRM SMS Log.

---

## User Role
- **Actor**: Registered Internet Banking Retail Portal customer
- **CRM Access Required**: QA/automation agent accessing CRM SMS Log to retrieve OTP during automated test runs

---

## Preconditions
1. The user must have a valid, active Internet Banking account.
2. The username (Sherif Rizk) must exist in the system.
3. The National ID associated with the account must match the registered record.
4. The user's mobile number must be registered and capable of receiving SMS.
5. The CRM SMS Log URL must be accessible for OTP retrieval.
6. CRM credentials must be configured in `.env`.
7. The portal must be reachable at `PORTAL_BASE_URL`.

---

## Negative Scenarios
| Scenario ID | Condition | Expected Error |
|-------------|-----------|---------------|
| FP-NEG-001 | Username field empty | Validation error: username required |
| FP-NEG-002 | National ID field empty | Validation error: national ID required |
| FP-NEG-003 | Invalid / unregistered username | Error: user not found or invalid credentials |
| FP-NEG-004 | Invalid National ID | Error: national ID mismatch or not found |
| FP-NEG-005 | OTP field empty on verify | Validation error: OTP required |
| FP-NEG-006 | Wrong / expired OTP entered | Error: invalid or expired OTP |
| FP-NEG-007 | New password and confirm password do not match | Validation error: passwords do not match |
| FP-NEG-008 | Terms and Conditions not checked | Validation error: T&C acceptance required |
| FP-NEG-009 | Password does not meet policy rules | Validation error: password policy not met |

---

## Validation Rules (Extracted)
1. Username is mandatory.
2. National ID is mandatory.
3. Both username + National ID must match a registered account record.
4. OTP is mandatory.
5. OTP must be valid (correct value, within expiry window).
6. New Password and Confirm Password must match.
7. Terms and Conditions checkbox must be checked before reset.
8. New password must meet password policy (complexity assumed: uppercase, lowercase, digit, special char).

---

## OTP Dependency on CRM
- OTP is generated by the portal backend and delivered via SMS to the registered mobile.
- The CRM SMS Log captures the outbound SMS message.
- QA retrieves the OTP from the CRM SMS Log using the Message Details section.
- OTP message format: `"Please use the following OTP to complete your authentication: <OTP>"`
- OTP regex: `/Please use the following OTP to complete your authentication:\s*(\d+)/i`
- **CRM URL (from .env)**: `CRM_SMS_LOG_URL`
- OTP must never be printed in plain text in logs or reports — masked value only.

---

## Sensitive Data Handling Rules
| Data Element | Handling Rule |
|--------------|--------------|
| National ID | Read from `.env`; never print in logs or reports |
| OTP | Extract from CRM; mask as `OTP:[***]` in logs |
| Current password | Read from `.env`; never print |
| New password | Read from `.env`; never print; shown as `****` |
| Username | May appear in logs as identifier only |

---

## Risks
1. **CRM availability**: If CRM is down or inaccessible, OTP cannot be retrieved — tests FP-003 through FP-006 will be blocked.
2. **CRM credentials not configured**: Placeholder `CRM_USERNAME`/`CRM_PASSWORD` in `.env` will block CRM login.
3. **OTP expiry**: OTP has a limited validity window; slow test execution may result in expired OTP.
4. **Password reset side effect**: Executing FP-005 changes the account password; subsequent runs must use the new password.
5. **National ID sensitivity**: Must never appear in screenshots, logs, or reports.
6. **Session blocker**: Portal may show "active session" dialog before login — handled via existing `LoginPage` pattern.
7. **Portal downtime / maintenance**: Tests cannot run if portal is unreachable.

---

## Assumptions
1. The Forgot Password link is visible on the portal login page without authentication.
2. The portal uses a single-page application (SPA) with hash routing — navigation is client-side.
3. OTP is numeric only (digit-only regex pattern).
4. OTP message format is stable and consistent: same template every time.
5. CRM SMS Log is sorted with the latest record first (or the most recent record is accessible).
6. The Terms and Conditions checkbox is a standard HTML checkbox or accessible role="checkbox".
7. Password policy requires: minimum length, uppercase, lowercase, digit, and special character.
8. After password reset, the new password `Test@2026` is valid per policy.
9. "Back To Logon" navigates back to the login page.
10. The portal login after password reset follows the same flow as the standard login flow (including session blocker handling).
